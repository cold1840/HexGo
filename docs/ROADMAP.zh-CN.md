# HexGo 路线图

本路线图表达发展方向，不承诺发布日期。每个阶段只有在满足验收标准后才算完成。优先级可通过经过审查的提案调整，但规则变更必须获得明确批准并同步更新两种语言的规则文档。

## 阶段 0：项目基础

目标：让仓库适合多语言、人类和 AI 辅助的协作，并且容易理解、流程安全。

- 发布作为规范基准的英文文档和官方简体中文翻译。
- 定义贡献、安全、社区行为、AI 和受保护分支流程。
- 在 CI 中保持格式、lint、构建和测试关卡。
- 按照 `BRANCH_PROTECTION.zh-CN.md` 配置 GitHub 分支保护。

验收标准：

- 新贡献者只依靠仓库文档就能配置环境、运行项目、验证改动并创建提案。
- 仓库设置阻止直接向 `main` 推送。
- 所有文档链接和语言版本配对均有效。

## 阶段 1：规则引擎

目标：将完整 HexGo 规则实现为独立于 Bevy 的确定性 Rust 逻辑。

- 构建并验证顶点—边棋盘图。
- 表示游戏配置、占用状态、回合、行动和结果。
- 实现棋串、不重复的气、提子、禁止自杀和全局同形禁着。
- 实现 Pass、认输、游戏结束、空域、面积计分和贴目。
- 为每条规范规则添加小型图结构测试数据和完整的单元、集成测试。

验收标准：

- 自动化测试覆盖 `RULES.md` 中的全部行为。
- 非法行动保持状态不变。
- 规则引擎可无界面运行且不依赖 Bevy。

## 阶段 2：本地可玩游戏

目标：通过 Bevy 提供完整的本地双人游戏。

- 清晰渲染棋盘图、可落子顶点和棋子。
- 支持选择交点、落子、Pass、认输、重新开始和对局配置。
- 显示当前行棋方、非法行动反馈、连续 Pass、游戏结果和分数明细。
- 从领域状态同步渲染，并提供易用输入和清晰可辨的视觉状态。

验收标准：

- 两名玩家可从启动到结果完成一局规则正确的游戏。
- UI 行动无法绕过领域验证。
- 核心流程具有针对性的自动化检查和有文档记录的人工冒烟测试。

## 阶段 3：持久化、回放与发布准备

目标：让对局可复现，并准备可靠的可分发构建。

- 定义不与渲染状态耦合的版本化存档和回放格式。
- 支持加载、回放导航，以及对无效或不兼容文件的清晰报错。
- 改进设置、上手引导、无障碍支持、诊断和平台打包。
- 建立发布说明、版本策略、支持平台检查和发布产物流程。

验收标准：

- 完成的对局可以确定性地保存、加载和回放。
- 无效数据安全失败，且不会破坏当前状态。
- 支持平台的构建通过已记录的发布检查。

## 未来候选方向

以下方向尚未承诺，均需要单独提案：

- AI 对手、局面分析和用于贴目研究的自我对弈；
- 在线多人游戏和观战；
- 匹配、账号、排名或托管服务；
- 更多棋盘预设和竞技规则配置。

未来 AI 和网络客户端必须使用与本地玩家相同、经过验证的游戏命令接口。
